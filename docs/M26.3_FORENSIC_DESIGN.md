## 1. Фактический production call graph (relevant to M26.3)

```
ConversationAgent._execute_chain(session_id, subtasks, ...)
  → ExecutionChain.execute(subtasks, chain_id)
      для каждого шага: _execute_chain_step()
          → planner.plan() → prepare() → engine.execute() → Job
          → output_assets ингестятся как Asset (type="video" для video шага)
  → result = chain.execute(...)                        # ЗДЕСЬ видео УЖЕ сгенерировано и ингестировано
  → intent = ctx.messages[0].get("turn", "")
  → M25 block (conversation.py:573-645):
        • Verifier.verify_sequence(sequence_ids)        # структурная (M4)
        • SemanticVerifier.verify_temporal_consistency(image_seq_paths)   # M25.3, INPUT image-sequence
        • build_chain_experience + build_sequence_experience → experience_store.record(exp)
  → return result.steps[-1].job                        # Job видео
```

**Где физически доступен GENERATED output video (п.1):**
- `result.steps[-1].job.output_assets[0]` → `store.get(aid)` → `Asset` с `Asset.path` (абсолютный путь к файлу `.mp4`/`.webm`).
- Файл уже записан на диск к моменту post-chain блока (ингест произошёл внутри `engine.execute()`).
- То есть видео материально доступно, но **не разбито на кадры**.

## 2. Что уже существует (п.2)

| Компонент | Наличие | Применимость к OUTPUT-video |
|-----------|----------|----------------------------|
| `SemanticVerifier.verify_temporal_consistency(sequence_assets)` | ✅ `semantic_verifier.py:266` | Принимает **список image-путей**; сравнивает consecutive пары через vision model. НЕ умеет читать видеофайл. |
| `SemanticVerifier.verify(output_path)` | ✅ `semantic_verifier.py:82` | Отправляет ОДИН файл как `image_url` (mime mp4/webm). Vision model (gpt-4o-mini) ожидает image, НЕ video → temporal continuity НЕ анализируется. |
| `TEMPORAL_CONSISTENCY_THRESHOLD = 0.5` | ✅ `semantic_verifier.py:27` | Существующий порог (M25.3, INPUT-sequence failure). Является архитектурным основанием (зеркалит semantic 0.5). НЕ magic. |
| INPUT-sequence temporal check (M25.3) | ✅ `conversation.py:594` | Анализирует ВХОДНЫЕ image-кадры до генерации. НЕ выходное видео. |
| Frame-extraction util (cv2/ffmpeg/ffprobe) | ❌ **ОТСУТСТВУЕТ** | Нет механизма получить кадры из видеофайла. |
| Video metadata util (duration/fps/frame_count) | ❌ **ОТСУТСТВУЕТ** | `avg_duration` в analytics/history — это duration выполнения, НЕ видео-метаданные. |

**Вывод (п.2/п.3):** существующий mechanism получения кадров/метаданных видео **отсутствует**. Temporal signal для OUTPUT-video через существующие компоненты **НЕВОЗМОЖЕН** без frame extraction (новая dependency) ИЛИ backend-предоставляемой метрики (ComfyUI `CreateVideo` не возвращает temporal score). Отправка всего видеофайла в vision model не даёт frame-to-frame continuity.

---

## 3. Gap (п.2/п.3)

1. **Frame extraction** — нужен generic util (video → frames). Нет в коде; предполагает dependency (imageio-ffmpeg / opencv / ffmpeg subprocess).
2. **Output-quality-gate semantics** — решение о том, является ли низкий output-temporal основанием для `JobState.FAILED`, требует отдельного AD.
3. **Threshold basis** — `0.7` НЕ имеет контракта. Единственный существующий — `0.5` (`TEMPORAL_CONSISTENCY_THRESHOLD`, M25.3 INPUT). Новый magic threshold вводить запрещено.

---

## 4. Что означает temporal consistency для media-agnostic контракта (п.4)

`temporal_consistency` — vision-model метрика визуальной continuity между consecutive кадрами (0.0–1.0). Media-agnostic в том смысле, что verifier обрабатывает любую пару image-кадров генерически (нет media-type ветвления в ядре — AD-03 соблюдён). Но семантически применимо только к video/animated output; для одиночного ассета возвращает `None` (как в M25.3: single asset → `temporal_score=None`, neutral).

| Понятие | Семантика | State change |
|---------|-----------|--------------|

## 6. Контракты, затрагиваемые при quality-gate (variant B) (п.6)

- **JobState** — post-hoc установка `FAILED` + `error_class="verification"` (как M25.3 `conversation.py:610` и `agent.py:639`).
- **SemanticVerifier** — переиспользование `verify_temporal_consistency` с extracted frames (метод уже есть; меняется ТОЛЬКО caller + источник кадров). Новый verifier subsystem НЕ нужен.
- **Verifier (M4, structural)** — НЕ затрагивается.
- **Experience / ChainExperience** —输出 temporal записывается как факт. Поле `temporal_consistency` уже существует (M25 заполняет INPUT-значением). Для OUTPUT нужно либо переиспользовать, либо добавить аддитивное поле `output_temporal_consistency` (additive, в рамках M25 envelope, но требует решения).
- **ExecutionRecord** — **НЕ изменяется** (жёсткое ограничение). Output temporal остаётся в ChainExperience.
- **ConversationAgent** — gate выполняется в post-chain блоке `_execute_chain` (рядом с M25.3 INPUT-check).

## 9. Существующий threshold (п.9)

## 10. Сравнение вариантов (п.10)

### Variant A — Advisory-only
Generated video остаётся **SUCCESS**; temporal score записывается как quality signal / experience.

- **Изменение production semantics:** отсутствует (Job всё так же SUCCESS).
- **Затрагиваемые контракты:** ChainExperience (additive `output_temporal_consistency` или reuse), ExperienceAnalytics (отражает output signal), ConversationAgent (запись в post-chain block). JobState/Verifier/ExecutionRecord — НЕТ.
- **Риски:** низкие; нет false-negative rejection сгенерированного видео.
- **Необходимые компоненты:** frame extraction (для получения signal) ИЛИ backend-метрика; запись в Experience.
- **Необходимость frame extraction:** **ДА** (для самого signal). Без него signal = None → advisory пуст.
- **Новый AD:** **НЕТ**.
- **Влияние на Experience:** output temporal становится фактом (обогащает M26.1 analytics).
- **Влияние на Planner:** косвенное (через M26.2 experience-preference, когда накопится signal).
- **UX:** пользователь видит quality signal / suggestion; видео не отбрасывается.
- **Тестовый объём:** малый (запись поля + analytics).
- **Invariants:** полностью совместим (Experience=fact, AD-18 neutral, AD-03 generic extractor).

### Variant B — Output-quality gate
Низкий temporal score → **FAILED / verification failure**.

- **Изменение production semantics:** Job видео может стать FAILED по quality (post-hoc), запуская retry loop.
- **Затрагиваемые контракты:** JobState (FAILED), SemanticVerifier (caller с frames), ChainExperience (recording), ConversationAgent (gate block). Verifier(M4)/ExecutionRecord — НЕТ.
- **Риски:** false-negative rejection легитимно сгенерированных видео (vision scoring субъективен); retry-cost; потенциально противоречит "Experience = fact, not rule" если трактовать как запрет.
- **Необходимые компоненты:** frame extraction + gate block + threshold (reuse 0.5).
- **Необходимость frame extraction:** **ДА**.
- **Новый AD:** **ДА** (AD-44 draft).
- **Влияние на Experience:** записывается как факт (как и в A).
- **Влияние на Planner:** через M26.2 (experience-preference на основе FAILED/low-quality истории).
- **UX:** видео с низким temporal может быть отброшено и перегенерировано (возможно нежелательно без согласия).
- **Тестовый объём:** средний (gate + negative/neutral paths + retry integration).
- **Invariants:** совместим при reuse 0.5 и post-hoc паттерне (как M14/M25.3), НО требует AD валидации.

## 12. Рекомендованный вариант

**Variant A (Advisory-only)** — как первый, безопасный шаг:
- не требует нового AD;

# PART 2 — Architectural Redefinition (2026-09-11)

## 19. Итоговое архитектурное решение

M26.3 переопределяется из «извлечь кадры из output video → посчитать temporal consistency → SUCCESS/FAILED» в **интеграционный boundary между ComfyUI Agent и будущим отдельным проектом Video Editor / Media Project**.

**Обоснование:** у проекта появится отдельный Video Editor, чья ответственность — монтаж/сборка episodes, timeline, transitions, audio/sync, effects, final render/mastering, **анализ и обработка готового video, включая video-specific frame extraction и media processing**. ComfyUI Agent **не должен превращаться в видеоредактор**. Поэтому video-specific analysis НЕ реализуется внутри Agent Core.

**Новая семантика M26.3 — Downstream Media / Video Editor Integration Boundary:**
- Agent может передавать downstream-проекту generated assets / episodes и необходимый контекст.
- Video Editor выполняет собственную media-specific обработку.
- Video Editor возвращает Agent результат обработки в виде формализованного integration result / status / metadata / feedback.
- Agent может использовать возвращённый результат как Experience/feedback для последующего планирования.
- Agent не обязан знать внутреннюю реализацию Video Editor.

## 20. Разделение ownership (Agent ↔ Video Editor)

| Ответственность                            | ComfyUI Agent | Video Editor |
| ------------------------------------------ | :-----------: | :----------: |
| User intent                                |      ✓        |              |
| Capability selection                       |      ✓        |              |
| Workflow selection                         |      ✓        |              |
| Model binding                              |      ✓        |              |
| ComfyUI execution                          |      ✓        |              |
| Generated asset acquisition                |      ✓        |              |
| Agent-level verification                   |      ✓        |              |
| Experience / planning                      |      ✓        |              |
| Episode assembly                           |               |      ✓       |
| Timeline                                   |               |      ✓       |
| Transitions                                |               |      ✓       |
| Audio editing/sync                         |               |      ✓       |
| Video frame extraction for media analysis  |               |      ✓       |
| Video-specific quality analysis            |               |      ✓       |
| Final video render                         |               |      ✓       |

Не вводить FFmpeg/OpenCV/imageio-ffmpeg или иной video-processing subsystem в Agent ради M26.3.

## 21. Интеграционная граница (концептуальный flow)

```
ComfyUI Agent
  → generated assets / episodes
  → Video Editor API (future contract)
  → media processing / assembly
  → result + metadata + status + optional feedback
  → ComfyUI Agent Experience
```

Не проектировать сейчас конкретный HTTP API/schema. Определены только семантические сущности и направление данных:
- **Agent → Editor:** generated assets/episodes + контекст (capability, intent, params).
- **Editor → Agent:** integration result, status, metadata, optional quality/feedback payload.

## 22. Temporal consistency — разведение понятий

- **Input temporal consistency** — существующая ответственность Agent/M25.3 для sequence input (`SemanticVerifier.verify_temporal_consistency`). НЕ удаляется, НЕ переносится в video subsystem.
- **Output video temporal/media quality analysis** — downstream responsibility Video Editor.
- `SemanticVerifier.verify_temporal_consistency()` НЕ расширяется сейчас до video processing.

## 23. Disposition Variant A / Variant B

- **Variant A (advisory, старой формулировки) — НЕ реализуется сейчас.** Причина НЕ в том, что advisory signal плох, а в том, что его video-specific получение требует media-processing слоя, принадлежащего Video Editor.
- **Variant B / AD-44 — отменён как текущий Agent Core direction.** Draft AD-44 НЕ утверждён и НЕ реализуется.
- **AD-44 статус:** `DRAFT / SUPERSEDED / NOT ACCEPTED` — исходная постановка quality gate признана принадлежащей downstream media boundary.
- Исторические forensic findings (PART 1) сохранены.

## 24. Связь с Experience

- Agent может принимать от Video Editor downstream feedback и использовать его в Experience/analytics/planning в будущем.
- **НЕ менять** `ExecutionRecord`; **НЕ менять** `PlanContext`; Video Editor НЕ становится частью ComfyUI execution backend; Video Editor НЕ обязательная зависимость обычного generation flow.
- Связь — **optional downstream integration**:
  - обычный путь `Agent → ComfyUI → asset` работает независимо от наличия Video Editor;
  - расширенный путь `Agent → ComfyUI → episodes → Video Editor → final media` — отдельный orchestration/integration сценарий.

## 25. Future: Video Editor Integration (deferred item)

- processing status;
- final output;

**НЕ реализуется в текущем M26.3.**
