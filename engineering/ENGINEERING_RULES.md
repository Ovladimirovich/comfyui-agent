# ENGINEERING_RULES.md

Общие правила разработки (операционный слой поверх PROJECT_SPEC §4/§5).

1. **Минимальные изменения** — делай ровно то, что требует задача.
2. **Не переписывать архитектуру без архитектурного решения.**
3. **Не добавлять зависимости без обоснования** (указать в Task → Risks).
4. **Не дублировать существующие abstraction** (переиспользуй ComfyClient / AssetStore / …).
5. **Не обходить domain contracts** (Asset / Job / Capability / Workflow).
6. **Не делать image-specific исключения в media-agnostic ядре.**
7. **Не давать LLM прямого доступа к filesystem / ComfyUI nodes.**
8. **Не скрывать ошибки** — явная обработка, понятные сообщения.
9. **Не использовать mock там, где требуется real E2E** (M1–M4, M10).
10. **Не менять публичные contracts молча** (API / Provider / Asset / Manifest / execution semantics).

Нарушение любого пункта = остановись и вынеси на архитектурное решение (CHANGE_PROTOCOL).
